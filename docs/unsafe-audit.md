# Native unsafe inventory

This is the unsafe-site inventory that an AI-assisted independent source review (not a certification or formal audit) was run against at source `21df87991d833cd046fd5f9b74cd7451ab0aa257`; `src/` is byte-identical since then. Hardware execution still requires explicit owner admission. `native-contract.md` is the normative ownership contract. Portable `client`, `driver`, `framing`, `events`, `ingress` and `lifecycle` modules each forbid unsafe code. No native object has an unsafe Send/Sync implementation; no safety lint is waived.

- Local compile: Rust 1.99.1, Apple clang 21.0.0, SDK `MacOSX27.2.sdk` (27.2). Gate deployment target is macOS 13.0. CI's installed SDK is runner-provided and must be rechecked if it differs; no claim that every SDK version has identical implementation behavior.

- Foundation enables only the owner/run-loop, native-buffer, collection, string and error types needed here. ICC enables device/browser/camera/item and blocks. Camera-item/CoreGraphics types implement all required delegate methods, including ignored thumbnail/metadata notifications, not a second image pipeline. CoreGraphics enables CGImage with transitive framework support; no scanner features or ICC default feature set. `cargo tree -e features` records the actual resolved feature union. `cargo deny` checks MIT / Apache-2.0 licenses and advisories across that graph; Apple system frameworks are linked, not bundled.
- Source anchors below refer to actual pinned registry sources and SDK headers, not a hand-written ABI. Generated bindings are at [ICC 0.3.2](https://docs.rs/objc2-image-capture-core/0.3.2/src/objc2_image_capture_core/generated/), [Foundation 0.3.2](https://docs.rs/objc2-foundation/0.3.2/objc2_foundation/), [objc2 0.6.4](https://docs.rs/objc2/0.6.4/objc2/) and [block2 0.6.2](https://docs.rs/block2/0.6.2/block2/).

## Ownership and liveness proof obligations

1. `block2::RcBlock::new` copies the closure onto a heap block. `RcBlock::clone` copies/retains the block; drop releases one reference; capture disposal occurs at final release (`block2` `rc_block.rs:143-217,221-233,265-281`, closure disposal helper in `stack.rs`). The implementation explicitly TRUSTS ICC to maintain valid ownership for asynchronous invocation, including concurrent final release. The specific ICC headers do not specify exact retain duration. This is a trusted framework assumption, not discovered callback quiescence.
2. `CallbackIngress` captures only immutable request identity, `Arc<AtomicBool>` and bounded `SyncSender<Completion>`. `thread_safe` statically requires closure captures to be Send+Sync. Once-claim happens before copying. Duplicate/stale block invocations allocate no second payload and cannot settle another request. IDs never wrap or restart across session generations. Owner releases settled NativePending/block references; it does NOT await all foreign block disposal or apply a lifetime request-credit budget.
3. Native command/outgoing buffers are separate retained immutable NSData copies in NativePending BEFORE submission. They are released after operation completion is received, explicitly trusting ordinary API semantics that native input last use has ended by completion OR ICC independently owns any later use. The header does not specify stronger last-use timing; this is an accepted trusted semantic assumption, not proof derived from a comment. Final foreign block disposal is unrelated. The block captures NO native input. A definite-not-submitted admission rejection may release preparations without a native completion, because ICC was never called.
4. Delegate lifetime is a different problem from blocks. Exactly one stateless retained proxy and one disconnectable ingress survive for the process lifetime; exactly one runtime can be constructed. Late delegate callbacks never access retired owner state. Event ingress synchronization serializes disconnect/publication; stale removals can quarantine, never fulfill open/close. Browser/device native state stays main-thread confined even though proxy ingress tolerates foreign queues.
5. Client wait/drop never frees NativePending. One bounded owner-retained wait-interest token outlives reply delivery; a Timeout store after reply publication still requests closure. Post-receive admission rechecks old interest before replacing it, relying on the non-cloneable client's serial request ordering, not a disappearing pending record. Driver records pending state before backend submission, processes completion separately from events, waits for pending work before close, and quarantines failed close/removal. A missing callback or failed close can block the joined runtime indefinitely. Scoped worker ownership guarantees joining even during Rust unwinding; NativeOwner's fallback Drop retains its ONE unresolved graph on unexpected unwind instead of freeing callback-reachable inputs. Foreign callback quiescence is NOT claimed by joining owned worker execution.
6. Completion ingress has one slot, independent of events. Driver permits one unresolved request and consumes its completion before the next. A full completion slot sets a sticky independent atomic fault, observed by the owner even when no completion can queue. It reports CallbackFailure and quarantines without treating the fault as cancellation; unresolved native graph/input ownership remains. Production session/PTP block tests deliberately exercise this path. Wrapper buffers/queues are bounded, not framework allocations or foreign retention. Rust OOM aborts are outside recoverable error handling.

## Independent audit questions

- Admit the exact generated ABI/nullability/BOOL encodings and every method annotation, including unrequested thumbnail/metadata callbacks.
- Confirm the trusted asynchronous block validity assumption and accepted ordinary input-completion semantics (last use ended OR ICC owns later use); do not claim stronger header proof. Check fresh final admission and definite-not-submitted withdrawal.
- Confirm process-lifetime proxy retention, thread-safe disconnect, late duplicate/stale handling, and no retired native owner capture.
- Confirm main-thread confinement, exact selection/capability preconditions, input retention, retained timeout-interest handoff and serial replacement, close/quarantine/reopen transitions, overflow-fault quarantine, unwind keepalive and scoped join paths.
- Confirm bounds and source/license feature union. Controlled blocks and production-driver tests are evidence of behavior, not proof of framework safety.

The first callback buffer is interpreted as data and the second as a PTP response. Header names and the earlier sanitized experiment support this, but it remains a per-device validation hypothesis for the admitted read-only trial, not a universal protocol guarantee.

No hardware, helper termination, native settings changes, root action, tag, registry upload or visibility change is part of this gate.
